# DESIGN: Libcararian Web

最終更新: 2026-11-10 / 状態: 承認済み（自律実装の指示による） / 対応PRD: docs/PRD.md / 現行仕様: docs/CURRENT_SPEC.md

## 1. 用語集

| 日本語 | コード上の名前 | 意味 |
|---|---|---|
| 元ファイル | `SourceFile` | 追加されたPDF1つ。中身（バイト列）とページ情報を持つ |
| ファイルのまとまり | `FileGroup` | ページ一覧での1ファイル分の塊。ドラッグで並べ替える単位 |
| ページ | `PageItem` | 一覧に並ぶ1枚。元ファイルのページか、挿入した白紙のどちらか |
| 挿入した白紙 | `PageItem(kind: "blank")` | 利用者が入れた白紙 |
| 調整の白紙 | `padding` | 小冊子にするとき、4の倍数にするため末尾に自動で足す白紙。一覧には出さない |
| 並び | `Arrangement` | ファイルのまとまりの順番と、各まとまりのページ。出力の元になる |
| 通しページ | `SequencePage` | 並びを先頭から平らにした1枚。0始まりの位置を持つ |
| 出力方法 | `OutputMode` | `booklet`（一括結合・小冊子）／`songs`（曲ごと）／`pages`（ページごと） |
| 曲 | `SongRow` | 曲ごと分割の1行。No.・曲名・開始・終了 |
| 出力結果 | `OutputResult` | 作ったPDFの集まり。確認画面とダウンロードの元 |
| 面付け順 | `bookletOrder` | 中綴じ小冊子のときの、B4の1枚ごとの左右のページの組 |

## 2. ドメインの規則（不変条件）

**ファイルとページ**
1. 同じファイル（名前・サイズ・更新日時が同じ）は二重に追加できない。
2. 読み込めなかったファイルは、一覧に赤く表示するが、出力には含めない。出力を実行するときは、その旨を知らせる。
3. 元ファイルのページは、MVPでは削除も移動もできない。各まとまりの `pages` に、元のページが元の順番で必ず全部入っている。変えられるのは次の3つだけ。
   - 白紙の挿入。
   - 挿入した白紙の削除。
   - ページの回転（US-9）。
4. 白紙は、まとまりの先頭・ページの間・末尾のどこにでも入れられる。ファイルを並べ替えると、そのファイルに属する白紙も一緒に動く。

**回転**

3a. 回転は 0・90・180・270 のどれか。「回転」を押すたびに右回りに90°進み、270の次は0に戻る。白紙は回転できない。
3b. ページごと分割で「B5に変換しない」を選んだときは、元のサイズのまま、`/Rotate` に回転を足して出力する。

**ページ番号**

5. 番号は、通しページの位置で決まる。値は `位置 + 開始番号 − 表紙のページ数` で、現行版と同じ。
6. 白紙（挿入した白紙も、調整の白紙も）は番号を1つ消費するが、番号は印刷しない。
7. 位置が表紙のページ数より前のページには、番号を印刷しない。

**小冊子**

8. 調整の白紙を足したあとの総ページ数は、必ず4の倍数になる。
9. 寸法・縮め方・番号の座標・mmからptへの換算（×2.83）は、現行版の値をそのまま使う（CURRENT_SPEC.md）。

**曲ごと分割**

10. 開始と終了は、印刷されているページ番号で指定する。通しページの位置は `番号 − 冒頭ページ番号` で求める。白紙もページとして数える。
11. 曲の行は、次のどれかに当てはまると「エラー」になり、エラーが1行でもあると実行できない。
    - 必須項目が空。
    - 整数でない。
    - 開始が終了より後ろ。
    - 範囲がすべてページの外にある。
    - ファイル名に使えない文字（`\ / : * ? " < > |`）を含む。
    - 生成されるファイル名が、ほかの行と重なる。
12. 範囲の一部だけがページの外にはみ出す行は「注意」とし、実行はできる。はみ出したページは出力しない。
13. 曲名の前後の空白は取り除く。No. が空の行は、エラーにする（現行版のように1にはしない）。

**ページごと分割**

14. 連番は、通しページの位置に1を足したもの（3桁、ゼロ埋め）。挿入した白紙も1ページとして出力する。

**出力とプライバシー**

15. 並びや設定を変えたら、それまでの出力結果は古くなったものとして捨てる。確認画面には常に、今の設定で作った結果が出る。
16. PDFのバイト列は、ブラウザの外に送らない。

## 3. 状態遷移

**元ファイルの読み込み**

```
読み込み中 ──成功──→ 使える
     └────失敗──→ 読み込めない（理由を表示。✕ で外すだけ）
```

**出力の処理**

```
未実行 ──[確認]──→ 処理中 ──成功──→ 結果あり ──[ダウンロード]──→ 結果あり
  ↑                  │                  │
  │                  └──失敗──→ 失敗（通知を出す）
  └──── 並びか設定を変えた ──────────────┘
```

- 処理中に並びや設定を変えたら、その処理の結果は受け取らずに捨てる。
- 「処理中」の間は、「確認」ボタンを押せない。

## 4. データモデル

`schemaVersion: 1`（MVPではデータを保存しない。次の版で設定を保存するときに使う）

### SourceFile（元ファイル）

| フィールド | 型 | 必須 | 説明 |
|---|---|---|---|
| id | string (UUID) | ✓ | |
| name | string | ✓ | 元のファイル名 |
| size | number | ✓ | バイト数。重複の判定に使う |
| lastModified | number | ✓ | UNIXミリ秒。重複の判定に使う |
| bytes | ArrayBuffer | ✓ | PDFの中身。メモリの中だけに置く |
| status | `"loading" \| "ready" \| "error"` | ✓ | |
| error | string | | 読み込めなかった理由 |
| pageCount | number | | 読み込めたときだけ |

（実装時の変更）
- 当初はページごとの寸法・原点・回転（`SourcePageInfo`）を持たせる予定だったが、やめた。
- 理由: 出力のときに pdf-lib が元ファイルから直接読むので、画面側は使わないため。
- 原点がずれたPDFは、`src/pdf/render.ts` で、MediaBox を切り出し範囲にして正しく扱う。
- 読み込みの確認（ページ数と、壊れていないか）は、出力と同じ pdf-lib を使い、読み込み用の Worker で行う。

### Arrangement（並び）

```ts
interface Arrangement {
  groups: FileGroup[];          // 配列の順番 = 出力の順番
}
interface FileGroup {
  id: string;                   // UUID
  sourceId: string;             // SourceFile.id
  pages: PageItem[];
}
type PageItem =
  | { id: string; kind: "source"; sourceId: string; pageIndex: number; rotation: Rotation }
  | { id: string; kind: "blank" };
```

- `rotation` は、利用者が付けた回転（右回り。`0 | 90 | 180 | 270`）。
  - 元のPDFの `/Rotate` に足して使う。出力では「`/Rotate` + rotation」の角度で中身を回してから、枠に収める。
  - サムネイルも同じ角度で描く。
  - 2026-11-10 に追加した。
- 次の版でページ単位の編集（削除・並べ替え）を足すときは、`pages` を編集できるようにする。まとまりをまたぐページの移動に備えて、`PageItem` にも `sourceId` を持たせている。
- 通しページ（`SequencePage[]`）は、並びから毎回計算する。保存はしない。

### 出力の設定

```ts
interface BookletSettings { fileName: string; booklet: boolean; centerGapMm: number;  // 初期値 20
                            numbering: boolean; startNumber: number; coverPages: number } // 1, 0
interface SongsSettings   { prefix: string; initialPage: number; rows: SongRow[] }
interface SongRow         { id: string; number: string; name: string; start: string; end: string }
interface PagesSettings   { prefix: string; convertToB5: boolean }                        // true
```

- `SongRow` は、入力された文字をそのまま持つ。検証して数値に直すのは、ドメインの関数 `validateSongs()` の役目。その結果として、行ごとのエラーと注意、変換した値を返す。

### OutputResult（出力結果）

| フィールド | 型 | 説明 |
|---|---|---|
| mode | OutputMode | |
| files | `{ name: string; bytes: Uint8Array; pageCount: number }[]` | |
| createdFrom | string | 並びと設定から作るキー。今の状態と違えば、古い結果とみなす |

**関係:** SourceFile 1 : FileGroup 1 です。FileGroup 1 : PageItem 多 で、PageItem は SourceFile の1ページか、白紙を指します。

## 5. 画面と URL

画面は1つで、URLは `/` だけです。共有したい状態がないので、ルーティングは使いません。

| 画面・部品 | 目的 | 主な要素 |
|---|---|---|
| ヘッダー | ファイルの操作 | アプリ名、［PDFを追加］［名前順］［クリア］ |
| ページ一覧（左、広い） | 並びを見て整える | ファイルのまとまり（ファイル名・ページ数・✕・ドラッグの取っ手）、ページのサムネイル（通しページ番号つき）、ページの間の［＋白紙］、白紙の［✕］ |
| 設定パネル（右、上下に固定） | 出力方法と設定 | タブ［小冊子｜曲ごと｜ページごと］、各タブの入力欄、［確認］（主要ボタン） |
| 確認画面（重ねて表示） | 出力を見てダウンロードする | 小冊子: B4の1枚ずつ、前へ・次へ。曲ごと・ページごと: 左にファイルの一覧、右にプレビュー。［ダウンロード］（主要ボタン）、［閉じる］ |
| 進捗と通知 | 処理の状況を伝える | 進捗バー（処理したページ数／全ページ数）、右下に出る通知 |

**状態ごとの見え方**

- **空:**
  - ページ一覧の全体を、ドロップゾーン（ファイルを落とす場所）にする。案内は「PDFをここにドロップ／またはクリックして選択」。
  - 設定パネルは表示するが、［確認］は押せない。理由として「PDFを追加してください」と添える。
- **読み込み中:**
  - まとまりの枠と、ページ数ぶんの灰色の枠を先に出す。
  - サムネイルは、画面に見えている分から順に描く。
- **エラー:**
  - **ファイルが読めない:** そのまとまりを赤い帯にし、理由と ✕ を出す。
  - **曲の入力ミス:** その行を赤くし、理由を行の下に出す。
  - **処理に失敗した:** 通知で知らせる。設定はそのまま残す。
- **通常:** 上の表のとおり。

**幅が860px以下のとき**は1列にします。順番は、ページ一覧 → 設定パネルで、設定パネルの固定は外します（デザインシステムの規則）。

## 6. 状態管理

| 状態 | 種類 | 置き場所 |
|---|---|---|
| 元ファイル（bytes を含む） | アプリ全体のデータ | ストア（`sources`） |
| 並び | アプリ全体のデータ | ストア（`arrangement`） |
| 選んでいる出力方法、各タブの設定 | アプリ全体のデータ（確認とダウンロードが参照する） | ストア（`settings`） |
| 出力結果、処理の状態、進捗 | アプリ全体のデータ | ストア（`job`） |
| サムネイルの画像 | キャッシュ | `lib/pdfjs` の中のキャッシュ（ページの id から画像 URL を引く） |
| 曲の行ごとのエラー、通しページ、出力ファイル名 | 派生 | 保存せず、毎回計算する |
| 確認画面の開閉、表示中の枚数 | UI | そのコンポーネントの中 |

ページ一覧・設定パネル・確認画面という離れた部品が、同じ並びと設定を読み書きするので、小さな全体ストア（Zustand）を1つ置きます。

## 7. アーキテクチャ

```
src/
  domain/            # 純粋な型と関数。DOM も pdf-lib も知らない
    arrangement.ts   #   白紙の挿入・削除、並べ替え、平らにする（sequence）
    numbering.ts     #   番号の値、番号を付けるかどうか
    booklet.ts       #   面付け順、調整の白紙の枚数、横方向の倍率
    songs.ts         #   validateSongs()、ファイル名の生成と検査
    constants.ts     #   現行版の寸法と座標
  pdf/               # pdf-lib で出力を作る。Worker の中で動く
    geometry.ts      #   回転と原点を含めて、枠に収める変換行列
    render.ts        #   renderBooklet / renderSongs / renderPages
    inspect.ts       #   元ファイルのページ情報を読む
  worker/
    jobs.worker.ts   # メッセージを受けて pdf/ を呼び、進捗と結果を返す
  features/
    files/           # ドロップゾーン、ページ一覧、ドラッグでの並べ替え、白紙の操作
    settings/        # 3つのタブと、その入力欄
    preview/         # 確認画面
    job/             # 確認ボタン、進捗、Worker を呼ぶ処理、ダウンロード
  lib/
    pdfjs.ts         # サムネイルとプレビューを描く（一度に描く数を制限し、キャッシュする）
    zip.ts           # ZIP にまとめる
    download.ts
  store.ts           # Zustand
  components/ui/     # ボタン、タブ、通知、入力欄（デザインシステムに沿う）
  styles/tokens.css  # design-system/tokens.json から作る CSS 変数
compat/              # 現行版（Python）との出力を比べるテスト（以前のWeb化作業から持ってくる）
```

**依存の向き:** `features → store → domain`、`worker → pdf → domain`。domain は何にも依存しません。

Worker にはジョブごとに、元ファイルの bytes の写しと、平らにした通しページと設定を渡します。

## 8. 技術構成

| 項目 | 選んだもの |
|---|---|
| ビルド | Vite |
| 画面 | React |
| 言語 | TypeScript（strict） |
| スタイル | 素のCSSとCSS変数。値はデザインシステムのトークンを使い、Tailwind は使わない |
| 状態 | Zustand |
| PDFの生成 | pdf-lib。元のページを Form XObject（PDF内で使い回せる描画の部品）として埋め込み、変換行列で配置する |

| ドラッグでの並べ替え | @dnd-kit/sortable |
| ZIP | fflate |
| テスト | Vitest（domain と pdf）、compat（現行版の出力と画像で比べる）、Playwright（主な操作を1本） |
| 保存 | なし（MVP） |
| 公開先 | GitHub Pages（静的サイト、無料） |

## 9. 非機能要件

- **性能:**
  - 300ページで固まらないこと。
  - サムネイルは、見えている分だけを幅120px程度で描き、同時に描くのは4枚まで。
  - 出力の処理は Worker で行い、進捗はページ単位で出す。
- **アクセシビリティ:**
  - ボタンと入力欄にラベルを付ける。
  - ファイルの並べ替えは、キーボードでもできるようにする（dnd-kit の機能）。
  - 色だけで状態を伝えない。エラーは文字でも示す。
- **レスポンシブ:** 1280px幅のPCが基準。860px以下では1列にする。
- **セキュリティ:**
  - 外部への通信はしない。
  - CSP（読み込んでよい通信先を絞る設定）で `connect-src 'self'` にする。
  - 入力されたPDFは pdf.js と pdf-lib で読むだけで、スクリプトは実行しない（pdf.js の `isEvalSupported: false`）。
- **データの安全:** 保存しないので、消えて困るデータはない。ページを再読み込みすると作業が消える旨を、画面の目立たない所に書く。

## 10. 決定記録（ADR）

### ADR-001 処理はすべてブラウザの中で行う
- **状況:** 楽譜PDFを外に出したくない。無料で公開したい。
- **決定:** サーバを持たず、pdf-lib と pdf.js でブラウザの中だけで処理する。
- **代替案:**
  - サーバでPython（現行のコード）を動かす。一致は確実だが、PDFを送ることになり、費用と運用も要る。
  - Pyodide（ブラウザでPythonを動かす仕組み）。読み込みが重い（数十MB）。
- **影響:** 現行版と同じ出力を、TypeScript で作り直す必要がある。compat テストで一致を保証する。

### ADR-002 並びは「ファイルのまとまり＋ページの配列」で持つ
- **状況:** MVPでは白紙の挿入だけだが、次の版でページ単位の編集を足す。
- **決定:** `FileGroup.pages: PageItem[]` という形にする。
- **代替案:** 白紙を「どのファイルの何ページ目の後か」という印だけで持つ。MVPは単純になるが、ページ単位の編集を足すときに作り直しになる。
- **影響:** MVPでは、不変条件3を arrangement.ts の関数で守る。

### ADR-003 画面は React と Zustand で作る
- **状況:** ページ一覧・設定・確認画面が同じ状態を参照する。ドラッグでの並べ替えと、行ごとの検証表示がある。
- **決定:** React と Zustand。
- **代替案:** 以前のWeb化作業と同じ素の TypeScript。依存は少ないが、画面の更新を手で書く量が多く、ページ一覧の再描画を管理しにくい。
- **影響:** 以前の `src/ui/` は流用しない。`src/core/` の計算は domain/ と pdf/ に移して流用する。

### ADR-004 現行版との一致を、画像の比較で確かめる
- **状況:** 「印刷結果が現行版と同じ」が成功基準になっている。
- **決定:** 以前の作業にある `compat/`（同じ入力で Python 版と Web 版の出力を作り、ページごとに画像にして比べる）を持ってくる。CI（自動テスト）ではなく、手元で動かす。
- **代替案:** 目で見て比べる。漏れやすい。
- **影響:** 手元に Python と、pypdf・reportlab・pymupdf が必要。

### ADR-006 TypeScript は 6.0 系に固定する
- **状況:** TypeScript 7 が出ている。しかし、リントに使う typescript-eslint 8.72 が対応しているのは 6.1 未満まで。
- **決定:** `typescript@~6.0`。
- **代替案:** TS 7 にしてリントをやめる。品質の確認が1つ減る。
- **影響:** typescript-eslint が TS 7 に対応したら上げる。

### ADR-007 E2E は Playwright で、インストール済みの Chrome を使う
- **状況:** E2E のために Playwright 専用のブラウザ（約150MB）を落とすのは重い。
- **決定:** `channel: 'chrome'` で、手元の Chrome を使う。相手は本番ビルド（CSP 入り）にする。
- **代替案:** Playwright 同梱の Chromium。CI ではこちらが楽。
- **影響:** CI で E2E を回すときは、`npx playwright install chrome` が必要になる。

### ADR-008 CSP は本番ビルドにだけ入れる
- **状況:** Vite の開発サーバーはインラインのスクリプトを使うため、厳しい CSP だと動かない。
- **決定:** `vite.config.ts` のプラグインで、ビルドした index.html にだけ `<meta http-equiv="Content-Security-Policy">` を入れる。
- **CSP の中身:** `connect-src 'self' blob: data:` として、外部への通信を禁じる。
- **代替案:** ホスト側の HTTP ヘッダー。GitHub Pages では設定できない。

### ADR-005 ZIP は fflate で作る
- **状況:** 曲ごと・ページごとの出力をまとめる。日本語のファイル名がある。
- **決定:** fflate（小さくて速く、UTF-8 のファイル名に対応）。
- **代替案:** jszip（以前の作業で使っていた。大きくて遅い）。
- **影響:** なし。

## 11. 仮定

- 白紙は番号を1つ消費する（規則6）。例えば4ページ目に白紙を入れると、その次のページは5になる。製本の一般的な扱いに合わせた。
- ページごと分割では、挿入した白紙も1ファイルとして出力する（規則14）。
- 曲ごと分割の開始と終了は、白紙も含めた通しの番号で指定する（規則10）。
