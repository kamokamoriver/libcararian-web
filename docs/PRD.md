# PRD: Libcararian Web

最終更新: 2026-11-10 / 状態: 承認済み（2026-11-10）

## 1. 問題文

楽譜係（ユーザー本人）は、合唱団の練習や本番のたびに楽譜PDFを集め、小冊子にして印刷している。いまはWindows用の自作アプリ（Libcararian）でしのいでいるが、次の不満がある。

- 自分のWindows PCでしか使えず、仲間に作業を任せられない。
- 結果は印刷するまで確かめられない。
- 白紙や表紙の扱い、ページ番号の見た目を細かく決められない。
- ページを1枚消したい・差し込みたいときは、元のPDFを別のソフトで直す必要がある。

## 2. ユーザーと利用場面

- **主な利用者:** 楽譜係と、団の仲間。URLを知っている人が使う。ログインはない。
- **使う場面・端末:** 作業はPCが中心。スマホは、表示が崩れない程度に対応する。
- **成功とは:** 印刷にそのまま回せる小冊子、または曲ごと・ページごとのPDFが手元にあり、印刷する前に中身を確かめ終えている状態。

## 3. コアループ

楽譜が揃う
→ PDFをまとめて追加する
→ ページ一覧で順番と白紙を整える
→ 出力方法（小冊子／曲ごと／ページごと）を設定する
→ 出力結果をプレビューで確かめる
→ ダウンロードして印刷する

## 4. ユーザーストーリー（Must のみ）

### US-1 PDFを追加して全ページを一覧する

楽譜係として、複数のPDFをまとめて追加し、全ページを一覧で見たい。どのページが何番目に来るかを把握するためだ。

- **前提:** 何も追加していない。
- **操作:** ボタンかドラッグ＆ドロップで、PDFを複数追加する。
- **結果:**
  - 全ページがファイルごとにまとまり、サムネイルで並ぶ。
  - PDF以外のファイルと、すでに追加したファイルは除かれる。
  - 読み込めないファイルは、理由とともに表示される。

### US-2 ファイルの順番を整える

楽譜係として、ファイル（曲）の順番を変えたい。プログラムの曲順どおりに並べるためだ。

- **操作:** ファイルのまとまりをドラッグする。または「名前順」を押す。
- **結果:** 一覧の並びと、出力されるページの順番が変わる。
- **削除:** 各ファイルは ✕ で外せる。「クリア」は確認してから全部外す。

### US-3 好きな位置に白紙を入れる

楽譜係として、ページとページの間に白紙を入れたい。曲の始まりを見開きの左右に合わせるためだ。

- **操作:** ページ一覧のページとページの間で「白紙を挿入」を選ぶ。
- **結果:**
  - その位置に白紙が1枚入る。
  - 入れた白紙は、一覧から取り除ける。

### US-4 小冊子を作る

楽譜係として、B4見開きの中綴じ小冊子を作りたい。そのまま印刷して製本するためだ。

- **設定する項目:** 中央余白（mm）、ページ番号を付けるか、開始番号、表紙のページ数。
- **結果:**
  - 4の倍数に足りない分は、末尾に白紙が自動で入る。
  - 自動で足した白紙と、US-3 で入れた白紙には、ページ番号を印刷しない。
  - 縮め方と配置は現行版と同じ（横方向だけ縮める）。
  - 番号の位置は現行版と同じ。

### US-5 曲ごとのPDFを作る

楽譜係として、結合した楽譜を曲ごとのPDFに切り分けたい。曲ごとに配ったり印刷したりするためだ。

- **設定する項目:**
  - 接頭辞。自由に入力でき、混声・女声・男声を候補として出す。
  - 冒頭ページ番号。
  - 曲ごとに No.・曲名・開始・終了。
- **入力の確認:** 入力ミス、ページ範囲外、ファイル名に使えない文字、ファイル名の重複がある行は、実行する前に赤く示す。黙って飛ばさない。
- **結果:** `{接頭辞}{No.を2桁}{曲名}.pdf` の集まりが、ZIPで1つにまとまる。

### US-6 ページごとのPDFを作る

楽譜係として、全ページを1枚ずつのPDFにしたい。

- **設定する項目:** 接頭辞と、B5に変換するか（初期値はオン）。
- **結果:**
  - `{接頭辞}{3桁の連番}.pdf` の集まりが、ZIPで1つにまとまる。
  - B5に変換しない場合は、元のサイズのまま出力する。

### US-7 ダウンロードする前に出力を確かめる

楽譜係として、出力結果を画面で確かめてからダウンロードしたい。印刷してから失敗に気づくのを防ぐためだ。

- **操作:** 「確認」を押す。
- **結果:**
  - 小冊子なら、B4の1枚ずつを表示する。曲ごと・ページごとなら、ファイルの一覧から選んで表示する。
  - そのまま「ダウンロード」を押せる。1ファイルならPDF、複数ならZIP。

### US-8 PDFを外に出さない

団の仲間として、楽譜PDFがどこかへ送られることなく処理されてほしい。楽譜の権利と、団の資料を守るためだ。

- **結果:** すべての処理が利用者のブラウザの中で完結する。PDFはサーバへ送信されない。

### US-9 ページを回転する

楽譜係として、ページを90°ずつ回転させたい。横長に作られた楽譜が、縦長のB5に押し込まれて潰れるのを防ぐためだ。（2026-11-10 追加）

- **操作:**
  - ページ一覧で、各ページの「回転」を押す。
  - ファイル単位の「全ページ回転」を押す。
- **結果:**
  - 押すたびに右回りに90°回り、サムネイルにも反映される。
  - 回した角度は、ページの下に表示する（例: 90°）。
  - 結合・小冊子・曲ごと・ページごとのどの出力にも、回転が反映される。
  - 回転していないページの出力は、今までと変わらない。

## 5. スコープ

**Must（MVP）**
- US-1〜9（US-9 は 2026-11-10 にユーザーの要望で追加）。
- 現行版の3機能（一括結合・小冊子、曲ごと分割、ページごと分割）を、ページ一覧が中心の1画面で使えるようにする。
- 処理中の進捗表示と、完了・エラーの通知。

**Should（次の版）**
- ページ単位の編集（1ページずつ削除・並べ替え）。回転は US-9 として MVP に入れた。
- ページ番号の書式設定（位置・大きさ・書体）。
- 曲リストの読み書き（CSV・Excel）。
- 作業内容の保存（設定と曲リストをブラウザに残す。PDFそのものは残さない）。
- 目次の自動作成。

**Could**
- 各曲を見開きの左から始めるよう、白紙を自動で入れる。
- 裏表紙を最終ページに固定する。

**やらないこと（Non-goals）**
- ログインや利用者の管理。
- サーバへのPDFアップロードと、クラウドへの保存。
- 作業内容を複数人で共有・同時編集すること。
- B5とB4以外の用紙サイズ（A4やA3など）。
- 小冊子の縮め方を縦横比を保つ方式に変えること（現行版と同じにする）。
- スマホでの快適な編集。
- 英語など、日本語以外への対応。

## 6. 制約

| 項目 | 内容 |
|---|---|
| 端末 | PCのブラウザが中心（Chrome、Edge、Safari） |
| データの置き場所 | ブラウザの中だけ。サーバは持たない |
| 利用者数 | 団の仲間、数人〜数十人 |
| 公開範囲 | URLで渡す。検索で見つかってもかまわない |
| オフライン | 必須ではない |
| 外部連携 | なし |
| データ量 | 1回あたり数十ファイル、合計100〜300ページ程度（仮） |
| 費用 | 無料の範囲で公開する |

## 7. リスクと検証

| リスク | 検証方法（スパイク） | 結果 |
|---|---|---|
| ブラウザで現行版と同じ小冊子が作れるか（縮め方・配置・番号の位置） | pdf-lib などで1冊作り、現行版の出力と重ねて比べる | 未 |
| 数百ページのサムネイル表示や処理で、重くなったりメモリが足りなくなったりしないか | スキャンした大きな楽譜PDF（100MB前後）で、表示と処理の時間を測る | 未 |
| `/Rotate` 付きのページや、ページ枠の原点がずれたPDFを正しく扱えるか | 現行版で問題が起きたPDFで確かめる | 未 |

## 9. MVP 成功基準

- [ ] 同じ入力と設定で作った小冊子が、現行版の出力と見た目で一致する。違うのは、白紙に番号が付かない点だけ。
- [ ] 曲ごと分割で入力ミスのある行が実行前に示され、黙って飛ばされることがない。
- [ ] 実在の楽譜PDF 約100ページを追加してから、小冊子をダウンロードするまでが、操作を含めて3分以内に終わる。
- [ ] 団の仲間が、説明なしでURLを開き、小冊子を1冊作ってダウンロードできる。
- [ ] 処理中に、PDFがネットワークへ送信されていない（ブラウザの開発者ツールで確かめる）。

## 10. 仮定（ユーザー未回答・お任せで採用したもの）

- ページ単位の編集のうち、MVPに入れるのは「白紙の挿入」「挿入した白紙を取り除く」「ページの回転（US-9）」だけ。削除と並べ替えは次の版にする。
- ページ番号の書式設定は次の版にする。MVPでは位置も書式も現行版のままにする。（当初「番号が端で切れる」と書いたが、コードを読み直すと切れないことがわかったため、この修正はMVPから外した。）
- 曲ごと分割の曲リストは、MVPでは現行版と同じく手で入力する表にする。
- 処理はすべてブラウザの中で行う。この前提で、技術は Phase 2 で決める。
- 以前のWeb化作業（`03_開発/Libcararian_Web`）は、Phase 2 で再利用できる部分を参考にする。ただし仕様はこのPRDを正とする。
